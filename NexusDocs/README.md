# NexusDocs

Система автоматизированной подготовки официальных запросов.

## Запуск

```powershell
python -m pip install -r requirements.txt
python main.py
```

Запускать команды из каталога `NexusDocs` либо использовать настроенную
виртуальную среду проекта.

## Рабочий сценарий

1. Нажать «Новый запрос» и заполнить данные человека.
2. Человек сразу сохраняется в `nexusdocs.db`.
3. NexusDocs проверяет локальную `organizations.db` по адресу регистрации.
4. Отсутствующие шапки NexusDocs ищет через бесплатный режим ИИ Google
   без API-ключа. Google получает строгий запрос сразу на девять организаций.
5. Полный корректный комплект автоматически сохраняется в БД и используется
   при сборке Word. Ручной редактор открывается только как запасной вариант,
   если в ответе действительно отсутствуют обязательные реквизиты.
6. Сохранённый комплект повторно используется для этого адреса.
7. Создаётся один редактируемый Word-файл со всеми 15 запросами. Его можно
   проверить, при необходимости исправить вручную и распечатать целиком.
8. После подписания открыть на главном экране «Отправка запросов», выбрать
   человека и общий PDF, затем нажать «1. Разбить PDF». NexusDocs локально
   распознаёт исходящие номера, выделяет все запросы и сохраняет переносимый
   пакет отправки.
9. На компьютере с Outlook перенести всю папку пакета и дважды нажать файл
   `Создать черновики Outlook.cmd`. Устанавливать NexusDocs на этот компьютер
   не требуется. Если приложение там уже установлено, тот же пакет можно
   выбрать второй кнопкой в окне «Отправка запросов».

В общий PDF можно включать любой набор контейнеров, в том числе ранее исключённые
1, 2, 9, 10 и 11. Порядок запросов не важен: тип определяется только суффиксом
исходящего номера, поэтому `.5` всегда получает сокращение «нарк», даже если
находится в начале или конце файла. Многостраничный контейнер сохраняется одним
PDF: например, обе страницы `.9` (ВСУ по РВСН) попадут в один отдельный файл.
Если один исходящий контейнер использован для нескольких самостоятельных
запросов, каждый запрос сохраняется отдельно: первый как `5771.6`, следующий как
`5771.6.1`, затем `5771.6.2` и так далее. Страницы одного многостраничного запроса
при этом должны идти подряд. OCR также понимает склеенные варианты вроде `57776`
как `5777.6`.

В той же стопке разрешены запросы с другим исходящим номером. Они тоже
разбиваются, получают собственную дату из скана и, если в шапке распознана
электронная почта, попадают в черновики Outlook. Аббревиатура к чужому исходящему
номеру не добавляется. Для контейнеров выбранного человека выше `.15` отдельные
PDF и черновики также создаются без аббревиатуры. Итоговый Word используется для
уточнения электронной почты, когда он доступен, но для самого разбиения больше
не обязателен. Разбиение PDF никогда не пытается запускать Outlook.

## Поиск шапок через Google AI

API-ключ и подключение оплаты не требуются. NexusDocs открывает режим ИИ Google во
встроенном браузерном окне с отдельной сохраняемой сессией, подставляет адрес в
строгий шаблон и принимает только полный ответ из девяти пронумерованных шапок.
Если Google запросит вход или проверку, её можно пройти в том же окне. У поиска
есть трёхминутный тайм-аут, отмена и повторная отправка.

Перед отправкой программа показывает точный передаваемый адрес и просит
подтверждение. ФИО, паспортные данные, сведения о деле и номер квартиры Google
не передаются. Улица и дом используются для определения обслуживающих
администрации и территориальной избирательной комиссии.

После сохранения шапка привязывается к территории в `organizations.db` и
повторно используется без выхода в интернет.

В начальную базу импортированы девять проверенных шапок из готового комплекта
«Запросы Соколов А.В.» для адреса в п. Рисоопытный Красноармейского района.

## Результаты

Для каждого человека создаётся каталог:

```text
output/<ID человека>/
├── ФамилияИИ_дата_все_запросы.docx
└── К отправке/
    └── <имя общего скана>/
        ├── исх. № НОМЕР.3 от ДАТА комиссариат.pdf
        ├── исх. № НОМЕР.16 от ДАТА.pdf
        ├── ...
        ├── пакет_отправки.nexusdocs.json
        ├── create_outlook_drafts.ps1
        └── Создать черновики Outlook.cmd
```

Адрес получателя берётся из шапки запроса; для стандартных контейнеров точное
значение дополнительно сверяется с сохранённым Word. Если электронной почты в
шапке нет, отдельный PDF создаётся, но черновик Outlook для него пропускается.
Служебный файл хранит темы, адресатов и относительные имена PDF, поэтому пакет
можно перенести на другой компьютер целиком. Программа проверяет комплект перед
созданием писем и никогда не отправляет их автоматически.
